# Phase 1 results — empty until the matrix runs

`npm run bench:v1` writes here. Nothing in this directory is hand-written, and no
placeholder or estimated figure is ever committed: the same rule Phase 0 followed
when `benchmarks/v0-baseline/results/` sat empty for two days.

What lands here after a run:

```
v1-baseline-vus{5,10,20,50,100,500,1000}.json   frozen instrument — comparable to v0
v1-realistic-vus{10,50,100}.json                realistic mix — new series, starts here
v1-saturation-rate{5,10,20}.json                open model, real mix (F-17 fixed)
*.samples.json.gz                               per-request streams — GITIGNORED
```

Then:

```bash
npm run bench:report:v1      # SUMMARY.md, including the v0-vs-v1 delta table
npm run bench:attribute:v1   # distils the sample streams into failure-attribution.txt
```

Two rules the tooling enforces rather than trusting you to remember:

- **Only frozen-instrument rows are compared against v0.** `baseline.js` runs the
  25%-authentication mix the v0 numbers came from; `realistic.js` runs ~0.5%. The
  report refuses to pair them.
- **Censored rows are excluded from the comparison.** Once requests are abandoned,
  every latency quantile equals the client timeout rather than a response time, so
  a delta between censored rows measures where the queue overflowed (finding F-13).
